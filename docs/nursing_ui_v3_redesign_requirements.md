# 간호업무량 기반 실시간 간호지원체계: 발표 중심 UI 구조 재설계 (V3)

## 0. 작업 목적

현재 V2는 실제 기능과 상태 전이 구현은 상당 부분 완료되었으나, 화면 구조는 이전 Claude Artifact의 간호사 카드와 처방 상세를 거의 그대로 유지한다. 환자 및 처방 정보가 상시 펼쳐지고 추천 대상마다 커다란 카드를 반복하여 핵심 흐름인 **지원이 필요한 간호사 발견 → 추천 간호사 확인 → 배정 → 수락/거절 → 지원 진행**이 한눈에 드러나지 않는다.

이번 작업은 간격과 폰트만 손보는 작업이 **아니다**. 데이터와 핵심 동작은 유지하면서, 첫 화면의 정보 구조를 새로 설계하는 **V3 디자인 및 인터랙션 재구성**이다.

- 기존 React 프로젝트에 적용한다. 새 프로젝트 생성 금지.
- Pretendard 적용 여부를 확인하되, 폰트 변경만으로 작업을 완료했다고 판단하지 않는다.
- 기존 가상 데이터, 09:00 수치, 현재 지원 상태 전이, 계산 함수, 테스트는 가능한 한 보존한다.
- Agent Builder API는 아직 연결되지 않았다. 실제로 연동되지 않은 AI 기능을 연동된 것처럼 표기하지 않는다.
- 실제 업무 기준을 임의로 새로 만들지 않는다. 임시 기준은 결과 문서에 남기고 화면에서는 발표를 방해하지 않도록 다룬다.

## 1. V2 문제점과 수정 목표

| 현재 문제 | V3에서 바꿀 점 | 합격 기준 |
|---|---|---|
| 6개 간호사 카드가 세로로 매우 길다 | 모든 카드의 기본 상태를 **요약형**으로 만들고 상세는 선택 시 별도 패널이나 드로어에서 표시 | 1440×900에서 6명의 현재 상태가 첫 화면에 모두 보인다 |
| 카드마다 환자, NEWS, 등록번호, 활력, 처방 버튼이 상시 보인다 | 선택된 간호사와 환자에게만 단계적으로 상세 노출 | 선택하지 않은 카드에는 환자별 처방 행이 없다 |
| 추천 2건이 커다란 카드 2개로 반복된다 | 상단의 **지원 필요 목록은 간단한 행**, 선택된 1건만 **추천 및 배정 패널**에서 상세히 표시 | 김서연 또는 이하은 선택 즉시 오른쪽 1개 패널의 대상이 바뀐다 |
| 추천 근거가 글머리표와 설명문 위주다 | `지원 대상 → 추천 1순위` 비교 레이아웃, 근거는 작은 칩 2~3개 | 본문을 읽지 않아도 이름과 단계 차이가 즉시 보인다 |
| 모든 글자의 크기와 굵기가 비슷하다 | 정보 위계: 큰 업무량 수치, 단계 배지, 작고 적은 보조 라벨 | 5초 내 `높음 2명`, `추천 1순위 한지호`를 알 수 있다 |
| 지원 흐름이 버튼과 역할 전환 속에 흩어져 있다 | 현재 상태와 다음 행동이 한 곳에서 보이도록 한다 | 1분 내 배정부터 수락까지 설명할 수 있다 |
| 보조 지표가 메인 화면을 차지한다 | 인력 적정성과 구역 대기는 작은 요약 또는 접힘 영역으로 이동 | 추천과 간호사 업무 현황보다 시각적 비중이 낮다 |
| 캡처 결과가 일부 잘려 검증 불명확 | 실제 viewport 크기별 전체 화면 캡처를 제출 | 1366×768, 1440×900, 1920×1080 캡처에서 양쪽 영역 전체 확인 가능 |

## 2. 권장 첫 화면 레이아웃

```text
│ 간호업무량 실시간 간호지원체계          [09:00]  [현재 화면: 근무조 리더 ▼] [시연 제어] │
├────────────────────────────────────────────────────────────────────────────────────┤
│  [높음 2명]  [지원 필요 2건]  [지원 진행 0건]  [인력 업무량 256 / 기준 250분]       │
├──────────────────────────────────────────────┬─────────────────────────────────────┤
│ 간호사 업무 현황                              │ 지원 매칭 및 배정                    │

│                                              │  지원 대상       추천 1순위         │

│ [구역별 대기 요약] [최근 지원 활동 2~3건] [인력 적정성 상세보기]                  │
└────────────────────────────────────────────────────────────────────────────────────┘
```

### 구체적 배치 기준

- 데스크톱 메인 영역: 간호사 업무 현황 약 62~65%, 지원 매칭 35~38%. 단, 고정 픽셀 폭이 아니라 읽기 좋은 최소 폭을 기준으로 조정.
- 기존 `max-width: 1280px`를 무조건 유지하지 않는다. 1440, 1920 화면에서 넓은 작업 영역을 활용하되 읽기 좋게 `max-width: 1540~1640px` 내에서 조정.
- 간호사 카드: 데스크톱에서 기본 **3열 × 2행**을 우선 실험. 너무 좁은 폭에서는 2열 × 3행. 카드 높이가 내용에 따라 크게 달라지지 않도록 한다.
- 1440×900의 기본 리더 화면에서 6개 간호사 상태와 선택된 지원 추천, 배정 버튼이 **스크롤 없이 함께 노출**되어야 한다.
- 환자 및 처방 상세는 우선 선택한 간호사 기준으로 표시하고, 간호사 카드 전체 높이를 늘리지 않는 드로어, 모달, 별도 상세 영역 중 가장 적합한 방식을 선택한다.
- 기본 화면은 정보량이 적어야 하지만, 간호사 상세에서 `수행`, `확인중`, `대기로 복귀`, 대리 수행 등 실제 동작은 그대로 접근 가능해야 한다.

## 3. 간호사 요약 카드 재설계

### 기본 카드에 반드시 표시
- 간호사 이름, 구역, 업무 단계 배지
- **담당 업무량: 127분**처럼 가장 크게 보이는 숫자
- 환자 수
- KTAS 1 또는 2 환자가 있으면 작은 강조 배지로 표시. 0명은 기본 카드에서 생략하는 방향 권장.
- `처방 대기 6건`, `최장 대기 40분`을 압축 배지 또는 한 줄 통계로 표시
- 지원 관련 상태: `지원 필요`, `응답 대기`, `한지호 지원 중` 등 이벤트가 있을 때만 표시
- 클릭 가능성과 선택 상태가 명확할 것

### 기본 카드에서 숨길 정보
- 환자별 이름, 등록번호, NEWS 상세, 활력 주기, 처방 목록
- 행마다 두 개씩 붙은 `수행`, `확인중` 버튼
- 계산식 분해 및 임시 기준 설명

### 상세 패널에 표시
- 선택한 간호사의 환자 목록
- 환자 행: 이름, 병상 식별자, KTAS, NEWS, 활력 주기, 수행 대기 건수
- 환자별 처방: 처방명, 대기시간, `수행`, `확인중` 또는 `대기로 복귀`
- 예정 처방
- 상세에서도 무의미한 반복 라벨을 줄이고 정보 그룹 간 명확한 간격 유지

## 4. 지원 매칭 및 배정 영역: 이번 개편의 중심

### 4-1. 지원 필요 목록
- 지원 필요 건수와 대상 목록을 한두 줄짜리 행으로 표시.
- 기본 선택: 현재 지원 필요도가 높은 간호사 한 명. 예: 김서연.
- 다른 대상, 예: 이하은을 누르면 **동일한 추천 상세 영역**의 내용이 바뀜. 두 개의 동일한 큰 카드를 동시에 렌더링하지 않음.
- 인력 적정성 초과는 지원 매칭과 다른 성격이므로 요약 경고로만 표시.

### 4-2. 지원 추천 상세
- 위쪽에 **지원 대상(김서연, 높음, 127분)**, 아래쪽 또는 나란히 **추천 1순위(한지호, 여유, 0분)**를 시각적으로 연결.
- 추천 근거는 텍스트 설명이 아닌 배지: `여유`, `업무량 0분`, `현재 지원 없음`. 동일 문구를 여러 번 반복하지 않는다.
- `다른 후보 선택`을 하나의 컴팩트 드롭다운으로 제공.
- CTA는 하나의 강한 버튼: `한지호에게 지원 요청`. 추천 변경 후 버튼명 자동 반영.
- 미선택, 추천 없음, 배정 요청됨, 응답 대기, 거절, 수락, 진행 중, 종료 상태별로 제목과 다음 행동을 다르게 표시.
- 주요 동작 후 대상 및 후보 상태가 즉시 업데이트. 다른 대상에서 같은 지원자를 중복 배정할 수 없도록 유지.

### 4-3. 진행 흐름 표시
- 상태 스텝퍼는 3~4단계 정도로 제한: `추천 → 배정 요청 → 지원 진행 → 완료`.
- 거절 시 `거절 → 다음 후보 추천`을 동일 패널에 간결히 표시.
- 간호사 역할로 전환하면 **받은 지원 요청**이 페이지 상단의 눈에 띄는 알림으로 나타나고, `수락`, `거절` 행동은 명확히 구분.
- 수락 이후 카드 양쪽에 지원 상태를 표시하고, 상세 환자 목록에서 대리 수행 가능하도록 유지.
- 지원 기록은 처음에는 최근 2~3줄만, 전체 기록은 별도 모달.

## 5. 정보 위계 및 디자인 시스템

- 글꼴: **Pretendard**. 이미 적용했다면 재사용.
- 제목 20~24px, 핵심 수치 26~32px, 카드 제목 16px, 본문 14~15px, 보조 설명 최소 12~13px (과도한 10~11px 남용 금지).
- 화면 구조에 반복 가능한 간격 체계를 사용: 4, 8, 12, 16, 24, 32px. 카드 내 16px 이상, 섹션 간 24px 내외부터 조정.
- 버튼 클릭 영역 최소 높이 34~40px. `수행`, `확인중`은 상세 영역에만 배치.
- 높은 업무 단계는 빨간색, 보통 주황색, 여유 초록색. 색에만 의존하지 말고 라벨도 함께 표시.
- 임의의 배경색, 테두리, 글머리표, 중복 제목 남발 금지. 섹션마다 동일한 패턴으로 정렬.
- 텍스트 대비 향상, 과한 연회색 메타 텍스트 줄이기.
- 장식용 대형 그래프는 필요하지 않음. 숫자, 상태 배지, 관계 표시가 우선.
- `시연 제어`, `시연 기준`, `처방 분류 기준`은 기본 업무 흐름 밖에 두되 접근 가능.

## 6. 계산과 상태 관리: 유지해야 할 동작

- 기존 09:00 초기값과 규칙 기반 로직을 유지한다.
- `확인중` 처방은 수행 완료가 아님. 대기 건수에서는 제외, 담당 업무량에는 포함하는 현재 정책 유지.
- 추천 후보 필터 및 우선순위 유지, 중복 배정 차단 유지.
- 지원 배정은 요청 상태를 만들고 수락 후에만 업무량 감산.
- 수락, 거절, 재추천, 대리 수행, 종료, 지원 기록은 모두 작동해야 함.
- 1시간 뒤 예측을 다시 노출하지 않는다.
- 확정되지 않은 처방별 수행기준과 초과시간을 기본 화면에 다시 노출하지 않는다.
- 규칙 기반 추천을 `AI 분석 완료` 또는 Agent Builder 연동 완료라고 허위 표현하지 않는다.
- 불필요한 긴 시연 안내 문구를 기본 화면에 복원하지 않는다.

## 7. 구현 순서와 리뷰 게이트

### STEP A: 디자인 구조 제안
1. 현재 V2의 정보 밀집 원인을 요약.
2. 새 컴포넌트 트리 및 레이아웃 와이어프레임을 `docs/result/v3_layout_proposal.md` 작성.
3. 선택 간호사 카드, 환자 상세, 지원 매칭, 지원 응답 화면의 핵심 상태를 그림 또는 텍스트 와이어프레임으로 제시.
4. 이 단계에서 **기존 로직과 상태 모델을 크게 변경하지 않음**.

### STEP B: 구현
- 레이아웃과 정보 노출 방식을 실제 코드로 변경.
- 선택한 지원 대상과 선택한 간호사 상세를 안정적으로 상태 관리.
- 기존 기능, 역할 전환 및 모든 지원 상태 전이 유지.
- 라이트 모드 기본, Pretendard 및 타이포그래피 통일.

### STEP C: 기능 및 시각 검증
- `npm test`, `npm run build` 실행.
- 초기값, 배정, 수락, 거절 후 재추천, 지원 종료, 확인중 전환을 직접 점검.
- 1366×768, 1440×900, 1920×1080 **실제 viewport 화면 전체**를 각각 정확한 크기로 캡처. 필요시 별도 full-page 캡처도 제출.
- 실제 viewport 크기와 캡처 파일 픽셀을 기록. crop된 이미지만으로 가독성 검증을 완료했다고 주장하지 않음.
- 1440×900 첫 화면에서 6개 간호사 요약, 현재 선택된 추천 대상, 추천자 및 CTA 노출 확인.

## 8. docs/result 필수 결과물

- `docs/result/v3_layout_proposal.md`: 기존 문제, 레이아웃 선택 이유, 변경 전후 정보 위계
- `docs/result/v3_change_log.md`: 실제 수정 파일, 컴포넌트, 삭제/이동 정보, 변경된 화면 인터랙션
- `docs/result/v3_ui_review.md`: 타이포, 여백, 정렬, 카드 균형, 가독성 점검 및 수정 사항
- `docs/result/v3_test_report.md`: 명령 실행 결과, 핵심 동작 검사, viewport별 스크린샷 파일명
- `docs/result/v3_demo_walkthrough.md`: 리더 시점 60~90초 발표 시나리오, 대상 선택 → 추천 → 요청 → 간호사 전환 → 수락 → 기록
- `docs/result/screenshots/v3-*`: 실제 캡처 이미지들

모든 문서는 실제 작업 결과를 기록하며 미실행 테스트를 통과했다고 작성하지 않는다.

## 9. 실패로 판단할 결과

- 기존 6개 간호사 카드 내부에 환자 상세를 기본 펼침 상태로 유지하고 폰트나 색만 바꿈.
- 지원 요청 두 건을 서로 같은 형식의 대형 카드로 반복 표기.
- 가독성을 개선한다며 폰트를 11px 이하로 줄여 텍스트를 억지로 욱여넣음.
- 내용을 숨겨 핵심 버튼이 작동하지 않거나 상태 흐름이 끊김.
- 추천 근거를 반복 문장으로 늘리고 실제 관계(지원 대상 ↔ 추천 간호사)가 시각적으로 보이지 않음.
- 스크린샷을 일부 잘라 제출하고 전체 레이아웃 검증을 주장함.
