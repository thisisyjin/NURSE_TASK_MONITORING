# Cursor 추가 단계별 프롬프트

`CURSOR_START_PROMPT.md`를 한 번에 입력한 뒤, 작업이 너무 넓어져 산만할 때 다음 프롬프트를 순서대로 사용할 수 있다.

## 1. 기존 HTML 분석만 먼저 요청

```text
references/의 기존 HTML과 시연 PDF 2~8페이지를 분석해줘. 당장 구현하기 전에 HTML의 화면 구역, 실제 가상 데이터, 버튼별 이벤트, 09:00/09:15/09:45 상태 변화, 역할별 화면 차이를 docs/HTML_ANALYSIS.md에 정리해줘. 최신 간호부 답변과 충돌하는 구 규칙도 별도로 표시해줘. 화면에 없는 데이터나 임상 로직은 만들지 마.
```

## 2. React 화면 구현 요청

```text
HTML 분석 결과와 README, AGENTS.md에 따라 기존 시연 현황판을 React + TypeScript로 재구현해줘. 기존 UI의 시각적 구성과 카드 구조를 최대한 보존해줘. 먼저 정적 화면과 가상 데이터를 연결하되, 버튼은 이후 실제 동작을 붙일 수 있도록 컴포넌트 경계를 나눠줘. 새로운 디자인이나 불필요한 페이지는 만들지 마.
```

## 3. Zustand와 시뮬레이션 구현 요청

```text
현재 React 화면에 Zustand 상태 및 시연 이벤트를 연결해줘. 09:00에서 시작해 처방 수행, 지원 배정, 지원 종료, 09:15 및 09:45 진행, 환자 악화, 초기화가 모두 동작해야 해. 예측 AI는 만들지 말고, 값이 다른 시연 시점의 데이터를 섞지 마. 업무량 계산 값과 화면 값이 항상 일치하도록 만들고 단위 테스트도 추가해줘.
```

## 4. F1~F4 Mock 서비스 요청

```text
현재 화면의 계산 로직을 EvaluationService 인터페이스 뒤로 옮겨줘. F1 처방 분류, F2 업무량 산정, F3 처방 지연 판단, F4 지원 판단 및 추천을 각각 Mock 서비스로 구현하고 Promise 기반으로 호출해줘. 추후 Agent Builder API로 바뀌어도 React 컴포넌트를 수정하지 않는 구조로 만들어줘. 기존 관찰 및 활력 소요시간에 임의의 KTAS/NEWS 산식을 추가하지 마.
```

## 5. 화면과 최신 간호부 답변 비교 요청

```text
최신 간호부 답변 PPT 및 PDF와 구현 화면을 대조해줘. 특히 환자당 50분 인력 기준, NEWS 단계 상승, 우선 대상 지원 알림 10분 조기 적용, 추천 후보 수동 변경, 지원 불가 이유, 배정 수락 및 거절, 일반 간호사 정보 제한을 점검해줘. 화면에서 가능한 데모와 아직 구현하지 않은 운영 기능을 구분하고 docs/OPEN_QUESTIONS.md에 기록해줘.
```

## 6. Agent Builder Flow 연결 요청 (Flow가 준비된 뒤)

```text
현재 MockEvaluationService와 동일한 입력 및 출력 계약을 따르는 LangflowEvaluationService를 구현해줘. research lab Agent Builder의 실제 API Access 코드와 응답 JSON을 내가 제공할 테니 그 명세에만 근거해 요청 및 파싱 코드를 작성해줘. Flow ID는 config로 분리하고 비밀키를 브라우저 빌드에 삽입하지 마. 오류, 타임아웃, 중복 요청, 구버전 응답 덮어쓰기를 처리해줘. Mock 모드를 계속 유지해서 API 서버가 없어도 시연 가능하게 해줘.
```
