# 다음 작업 실행 계획

작성일: 2026-11-25

이 문서는 구현 전에 순서를 고정하기 위한 계획이다. 네 작업의 코드는 아직 시작하지 않는다.

기준 화면은 지금 React 앱의 `/`(1안), `/ver2`(2안)이다. 기존 UI 원본은 `references/nursing_artifact_standalone_light.html`이다. 이 원본 파일과 `docs/nursing_artifact_function_spec.md`, `nursing_artifact_reference/`는 수정하지 않는다.

## 진행 순서

1. `/backup` 페이지를 만든다.
2. 그 시점을 백업으로 남긴다. 1안과 2안은 이 백업 이후에만 고친다.
3. 1안, 2안 화면을 더 잘 보이게 다듬는다.
4. 최근 지원에서 들어가는 리포트 페이지와 다운로드를 넣는다.
5. 다듬은 1안, 2안만 단일 HTML로 추출한다.

3번은 2번 화면 수정과 파일을 같이 건드릴 수 있다. 그래서 2번 화면 수정이 끝난 뒤에 링크를 단다. 리포트에 쓸 데이터 항목은 2번과 별개로 미리 정해 둔다.

## 1. `/backup` 기존 UI 페이지

### 목표

라이트 원본의 배치와 시연 흐름을 `/backup`에서 다시 연다. 이전에 화면에서 빼기로 한 수행시간과 기준시간은 이 페이지에도 넣지 않는다.

원본 배치는 다음과 같다.

- 상단: 제목, 시연 시각, 보기 선택, `+15분 진행`, 자동 진행, 처방 발생, 간호요구 급증, CPCR 발생, 초기화, 단계 범례
- 왼쪽: 간호사 카드. 이름, 구역, 환자 수, 단계, 현재 업무량, 환자별 처방과 수행
- 오른쪽: 지원 알림, 지원 기록, 인력 적정성, 처방 적시성, 처방 분류 기준

지금 1안, 2안의 접기, 미색, 카드 폭, 지원 매칭 wide 배치는 가져오지 않는다.

### 화면에서 뺄 것

원본 문구를 그대로 두지 않고 아래만 표시에서 뺀다. 계산용 필드는 도메인에 남겨 둔다.

| 원본 표시 | `/backup` 표시 |
|---|---|
| `25분 · 대기 40/기준 30분` | `대기 40분` |
| `수행 기준 초과 N건` 칩, 처방 행의 초과 강조선 | 표시하지 않음 |
| 구역 표의 `기준 초과` 열 | 구역, 대기 건수, 최장 대기만 |
| `1시간 뒤 167분`, 옅은 예측 막대, 범례의 예측 문구 | 표시하지 않음 |
| 본문에 붙은 처방 분류 기준표 | 1안과 같이 푸터 링크로 열고, 표에 표준 소요시간 열은 두지 않음 |

카드의 대표 숫자는 원본처럼 현재 업무량이다. 1안, 2안 카드의 대기 처방 분으로 바꾸지 않는다. 관찰, 활력, 대기 처방 분해 줄도 원본에 있으므로 유지한다.

`확인중`은 원본에 없다. `/backup`에는 넣지 않는다.

### 실행

1. `src/main.tsx`의 경로 분기에 `/backup`을 추가한다. `/`와 `/ver2` 분기는 그대로 둔다.
2. `src/app/BackupApp.tsx`와 `src/styles/backup.css`를 새로 만든다. 스타일은 `.backup` 아래로만 적용한다.
3. 상태와 버튼 동작은 기존 `src/domain/artifact`의 초기 상태, 시간 진행, 수행, 지원 배정, 수락, 거절, 초기화를 재사용한다.
4. `/backup` 상태는 1안, 2안 스토어와 분리한다. 백업 화면에서 `+15분`을 눌러도 1안 시계가 같이 움직이지 않게 한다.
5. 처방 행 문구만 포맷 함수에서 `대기 N분`으로 만든다. `loadOf`, `dueOf` 계산식은 바꾸지 않는다.
6. 주요 버튼은 실제로 동작하고, 초기화하면 09:00 원본 상태로 돌아간다.

### 완료 기준

- `http://localhost:<port>/backup`에서 09:00 카드와 오른쪽 다섯 영역이 원본 순서로 보인다.
- 처방 행에 소요시간, `기준 N분`, 수행 기준 초과가 없다.
- 1시간 뒤 예측 숫자와 옅은 막대가 없다.
- `/`와 `/ver2`의 화면과 스토어는 이 작업으로 바뀌지 않는다.

## 2. 백업 뒤에 1안, 2안 다듬기

### 시작 조건

`/backup`이 위 완료 기준을 통과한 뒤, 그 커밋을 백업 지점으로 남긴다. 그 전에 1안, 2안의 배치를 다시 옮기지 않는다.

이전에 넣었다가 되돌린 카드 전체 접기, 하단 3열 이동은 다시 하지 않는다. 2안 상단 지원 매칭 및 배정의 가로 배치는 유지한다.

### 목표

데이터와 단계 규칙은 유지하고, 글자 크기, 간격, 제목, 표의 구분만 조정한다.

우선 볼 곳은 다음이다.

- 1안 오른쪽 열. 지원 매칭, 인력 적정성, 구역별 대기, 최근 지원이 한 덩어리로 보이지 않게 제목과 간격을 키운다. 2안에서 이미 적용한 흰색 카드 구분과 18px 제목을 1안에 맞출지 먼저 화면을 비교한다.
- 2안은 상단 매칭 배치는 고정하고, 카드와 오른쪽 열의 제목, 표 머리, 여백만 더 본다.
- 간호사 카드의 대기 처방 분, KTAS, 수행, 확인중은 지금 규칙을 유지한다.

### 실행

1. `/`와 `/ver2`를 같은 09:00 상태에서 나란히 보고, 고칠 항목을 이 문서 아래에 짧은 목록으로 추가한 다음 수정한다.
2. 스타일은 `src/styles/v3.css`, `src/styles/ver2.css`에서 각 화면 범위만 바꾼다. `.backup`과 도메인 계산은 건드리지 않는다.
3. 브라우저에서 1안, 2안 모두 눌러 본다. 수행, 확인중, 지원 요청, 접기, 초기화가 그대로 동작하는지 확인한다.

### 완료 기준

- `/backup` 화면이 1안, 2안 수정 후에도 같다.
- 단계 숫자, 대기 분, 지원 추천 순서가 스타일 수정 전과 같다.
- 상단 지원 매칭의 좌우 배치가 유지된다.

## 3. 최근 지원에서 리포트 다운로드

### 목표

1안, 2안의 최근 지원 제목 옆에 `리포트` 링크를 두고 `/reports`로 연다. 화면에서 간호사와 시연 시각을 고르고, 표를 본 뒤 파일을 받는다.

백엔드는 만들지 않는다. 브라우저에서 CSV를 만든다. UTF-8 BOM을 붙여 엑셀에서 한글이 열리게 한다. 파일명은 `간호업무_리포트_시연시각.csv` 형식이다.

### 데이터 범위

지금 메모리에 있는 것은 현재 시각의 보드와 지원 기록, 활동 문장이다. 시각별 업무량 이력은 없다. 따라서 `+15분`, 자동 진행, 초기화 시점에 간호사별 스냅샷을 추가로 쌓는다. 스냅샷 항목은 이미 계산 중인 값만 쓴다.

| 리포트 | 행 단위 | 열 |
|---|---|---|
| 시각별 업무 | 간호사, 시연 시각 | 간호사, 시각, 구역, 담당 환자 수, 대기 처방 분, 현재 업무량 분, 업무 단계 |
| 지원 기록 | 지원 1건 | 시각, 지원자, 대상, 시작, 종료 또는 진행 상태, 수행 건수 |
| 수행 기록 | 활동 1건 | 시각, 종류, 문장 |

날짜는 시연용 하루로만 둔다. 없는 과거 날짜를 만들어 채우지 않는다. 환자 등록번호와 직원 개인정보는 파일에 넣지 않는다. 환자명은 가상 데이터인 기존 시연 값만 수행 문장에 이미 있을 때 그대로 둔다.

업무 단계와 대기 분 규칙은 대시보드와 같은 함수를 쓴다. 리포트용 가중치는 만들지 않는다.

### 실행

1. 스냅샷 배열을 시연 상태에 추가하고, 시간 진행과 초기화 액션에서만 기록한다.
2. `src/app/ReportsPage.tsx`를 만들고 `/reports`에 연결한다.
3. `SupportHistoryPanel`에 링크를 추가한다. `/backup`의 지원 기록에는 넣지 않는다.
4. 다운로드 버튼은 화면에 보이는 필터 결과와 같은 행을 파일로 저장한다.
5. 초기화하면 스냅샷과 지원 기록도 09:00 상태로 돌아간다.

### 완료 기준

- 최근 지원에서 `/reports`로 이동한다.
- 09:00과 `+15분` 이후 시각별 업무 행이 달라진다.
- 받은 CSV를 다시 열면 화면 표와 행 수가 같다.
- 새로고침하면 메모리 기록은 사라진다. 화면에 그 한계를 한 줄로 적는다.

## 4. 1안, 2안 HTML 추출

### 목표

다듬기가 끝난 1안과 2안을, 서버 없이 브라우저로 열 수 있는 HTML 파일 두 개로 만든다.

포함: `/`, `/ver2`의 화면, 스타일, 시연 동작, 가상 초기 데이터.

제외: `/backup`, `/reports`, F2 API, 개발 서버.

### 실행

1. Vite 빌드 결과를 한 파일로 합친다. JS와 CSS를 HTML 안에 넣는다.
2. 결과 파일은 `export/nursing_ver1.html`, `export/nursing_ver2.html`이다.
3. 각 파일은 열릴 때 경로와 상관없이 1안 또는 2안만 그리도록 시작 값을 고정한다. `file://`에서는 `/ver2` 경로가 동작하지 않기 때문이다.
4. 추출 후 두 파일을 브라우저에서 직접 열어 `+15분`, 수행, 지원 요청, 초기화를 확인한다.
5. 원본 `references/nursing_artifact_standalone_light.html`은 덮어쓰지 않는다.

### 완료 기준

- 두 파일이 각각 1안, 2안 초기 화면을 연다.
- 네트워크 없이 버튼 동작이 된다.
- React 소스의 `/`와 `/ver2`는 추출 후에도 개발 서버에서 그대로 동작한다.

## 이번 계획에서 하지 않는 일

- 업무량 계산식, KTAS 강제 높음, 30분과 50분 단계 경계를 바꾸지 않는다.
- 간호사 순위, 실제 환자 정보, 실제 직원 정보를 추가하지 않는다.
- 별도 백엔드나 DB를 만들지 않는다.
- 시나리오 선택 UI를 다시 넣지 않는다.
