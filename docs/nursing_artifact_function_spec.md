# 간호업무량 기반 실시간 간호지원체계 — 기능 정의서 및 로직 분석

> 기준 소스: 사용자가 제공한 `demo.html`의 앱 코드(JavaScript 및 화면 마크업). 2026-11-23 분석.
> 이 문서는 **현재 원본 코드에 실제로 구현된 동작**을 정리한 것이며, 의료 현장에서 검증된 규칙을 의미하지 않습니다.
> 실제 환자 및 간호사 데이터는 포함되지 않으며, 소스 내 이름과 등록번호는 가상 데이터로 명시되어 있습니다.

## 1. 시스템 개요

- 실행 방식: 단일 HTML 안에 CSS, 순수 JavaScript 및 가상 데이터가 포함된 브라우저 시뮬레이션.
- 상태 저장: 메모리 변수 `S` 및 별도 `seq`, `autoT`. 서버 API, DB 연동 없음.
- 화면 구조: 상단 시연 제어 바, 간호사별 카드 그리드, 지원 알림 및 지원 기록, 인력 적정성, 처방 적시성, 처방 분류 기준 우측 패널.
- 권한: `leader`, `np`는 전체 상세 조회, 개별 간호사는 자신의 상세 및 동료 단계 조회, 지원 수락 중에는 지원 대상자의 상세도 조회.
- 시연 시간: 09:00 시작, `+15분 진행`, 자동 진행(현실 2초마다 시연 5분 증가).

## 4. 핵심 계산 및 판정 로직

### 4.1 F01 간호사별 현재 업무량

**환자별 관찰 부하**
- KTAS 기본값: 1등급 20분, 2등급 15분, 3등급 10분, 4등급 5분, 5등급 3분.
- NEWS 가산: 7점 이상 +10분, 5~6점 +5분, 0~4점 또는 null +0분.
- 환자별 관찰 부하 = `KTAS_LOAD[ktas] + newsLoad(news)`.

**환자별 활력징후 측정 부하**
- 1회 측정시간은 3분으로 고정.
- `Math.round((60 / vs) * 3)` 분. `vs`는 측정 주기(분).
- 예: 120분마다 측정 → `Math.round(1.5)` = 2분, 240분마다 측정 → `Math.round(0.75)` = 1분, 480분마다 측정 → `Math.round(0.375)` = 0분.
- 주의: 1시간 기준 기대 소요시간을 **환자별로 반올림**하므로, 이 수치는 실제 측정 횟수의 합계와 다를 수 있습니다.

**처방 부하**
- `orders`에 남아 있는 미완료 처방의 `min` 값을 모두 합산.
- **대기시간 자체나 목표시간 초과분을 더하지 않습니다.** 수행 완료 시 해당 처방이 목록에서 제거되어 처방 부하가 감소합니다.

**지원 감산**
- 수락하고 종료하지 않은 지원자가 `k`명이라면 `factor = max(0.35, 1 - 0.4*k)`.
- 최종 현재 업무량 = `Math.round((관찰 + 활력 + 미완료 처방) * factor)`.
- 지원자 1명: 업무량 60%로 감소, 2명 이상: 최저 35%로 제한.
- 이 감산은 실제 작업 분담 실적과 무관한 시연 규칙입니다.

**초기값 검산 (09:00)**

| 간호사 | 관찰 | 활력 | 미완료 처방 | 현재 업무량 | 업무 단계 |
|---|---:|---:|---:|---:|---|
| 김서연 | 40 | 4 | 83 | 127 | 높음 |
| 박도윤 | 15 | 1 | 15 | 31 | 보통 |
| 이하은 | 25 | 3 | 25 | 53 | 높음 |
| 최민준 | 8 | 0 | 3 | 11 | 여유 |
| 정유나 | 26 | 0 | 8 | 34 | 보통 |
| 한지호 | 담당 환자 없음 | 해당 없음 | 해당 없음 | 미표시 | 여유 (역할 기본값) |

### 4.2 F02 단계 판단

```text
환자가 없으면: 역할별 기본 단계
활성 간호요구 급증 이벤트가 있으면: 무조건 '높음'
그 외 현재 업무량:
  30분 미만: 여유
  30분 이상 50분 이하: 보통
  50분 초과: 높음
```

**중요:** 원본 코드는 `m > 50`이며 `m >= 50`이 아닙니다. 따라서 정확히 50분은 **보통**입니다. 이전에 협의한 기준이 `50분 이상 = 높음`이라면 변경해야 합니다.

### 4.3 F03 1시간 뒤 예측

```text
예측 업무량 = 현재 계산 원값(관찰 + 활력 + 미완료 처방 소요시간)
             + 앞으로 60분 이내에 예정된 처방 소요시간 합계
             + NEWS가 이전 위험 단계보다 상승한 환자당 5분
```

수락된 지원 인력이 있다면 현재 업무량과 예측 업무량에 동일한 감산 비율을 적용합니다. 미래의 KTAS/NEWS 변화를 모델로 예측하는 AI가 아니라 **예정된 일정과 현재 이벤트를 반영하는 규칙 기반 추산**입니다.

초기 예측값: 김서연 167분, 박도윤 41분, 이하은 63분, 최민준 11분, 정유나 44분.

### 4.4 F04 처방 지연 판단

```text
대기시간 = 현재 시연 시각 - 처방 발생 시각
기본 수행 기준 = 처방별 설정(DUE)이 있으면 해당 값, 없으면 30분
지원 우선 대상이면 기준 10분 단축
최종 수행 기준 = max(5분, 계산된 기준)
지연 = 대기시간 >= 최종 수행 기준
```

| 처방 | 기본 수행 기준 | 지원 우선 대상 지정 시 |
|---|---:|---:|
| 일반 미지정 처방 | 30분 | 20분 |
| 항생제(패혈성 쇼크) | 60분 | 50분 |
| CPR 진행 | 5분 | 5분 (하한 적용) |
| 에피네프린 투여 | 5분 | 5분 (하한 적용) |
| Intubation 준비 및 보조 | 10분 | 5분 (하한 적용) |

주의: **처방 소요시간**(`CAT`의 `min`)과 **수행 기준시간**(`DUE` 및 `DUE_DEF`)은 서로 다른 수치입니다.

### 4.5 F05 지원 알림 생성

| 알림 | 실제 조건 | 표시 및 조치 |
|---|---|---|
| 예측 | 현재 높음이 아니고 예측 업무량이 50분 초과 | 1시간 뒤 높음 예상, 선제적 지원 준비 |
| 1단계 | 현재 높음 또는 사용자가 직접 지원 필요 표시 | 동료 간 자발적 지원 요청 |
| 2단계 | 활성 간호요구 급증이 있고 아직 수락된 지원자가 없을 때. 또는 **현재 높음 / 직접 지원 요청 상태**에서 높음 30분 이상 지속, 수행 기준 초과 처방 일반 2건 이상 / 우선 대상 1건 이상 | 근무조 리더 및 응급전문간호사가 지원 또는 환자 재배정 검토 |
| 3단계 | 근무조 전체 업무량이 인력 기준 초과 | 간호관리자 보고, 추가 인력 요청 |
| 4단계 | 인력 기준 초과가 30분 이상 지속 또는 기준 초과 상태에서 CPR 팀 투입 중 | 간호관리자 및 부서 간 A-plus 지원 검토 |
| 긴급(E) | 종료되지 않은 CPR 상황 | CPR 팀 즉시 배정 및 현장 지원 |

보충 조건:
- 2단계 환자 급증 이벤트는 해당 간호사에게 수락된 지원자가 없을 때 우선 발생합니다. **초과 처방 건수가 많다는 사실만으로 일반 2단계 알림이 발생하는 것은 아니며, 현재 `높음`이거나 직접 지원 요청 상태여야 합니다.**
- 해당 간호사에게 수락된 지원자가 있으면 일반 지원 알림이 생략됩니다.
- 알림 정렬 순서: 긴급 → 4 → 3 → 2 → 1 → 예측.
- 4단계는 **인력 기준 초과 상태라는 선행 조건**이 있습니다. 단순히 CPR 팀이 투입되었다는 이유만으로 항상 4단계가 생기지는 않습니다.
- `hiSince` 및 `cap3Since`는 시연 시각을 기준으로 경과시간을 계산합니다.

### 4.6 F06 지원자 추천

**제외 조건:** 지원받을 당사자, 별도 제외 목록, 다른 사람을 지원 배정받고 종료되지 않은 간호사, 지원 우선 대상 간호사, 현재 높음 단계, 같은 대상에 대한 거절 이력이 있는 간호사.

**정렬:** 여유 간호사를 보통보다 우선하며, 같은 우선순위에서는 현재 업무량이 낮은 순서로 첫 번째 사람을 추천합니다.

처리되지 않은 세부 조건: 휴식시간, 업무 숙련도, 담당 병상 접근 거리, 특정 처치 가능 자격 등은 추천 필터로 구현되지 않았습니다. 거절 사유는 있지만 실제 가용성 정보 검증으로 이어지지 않습니다.

### 4.7 F07~F08 지원 배정, 수락, 거절, 종료 및 수행 기록

```text
지원 배정 클릭
  → supports 항목 생성: accepted=false, start=현재 시각, end=null, tasks=0
  → 지원자 개인 화면에서 수락 또는 거절
수락
  → accepted=true, start=수락 시각
  → 해당 간호사의 지원 대상 화면 상세 열람 가능
  → 지원 대상의 현재 및 예측 업무량에 감산 적용
거절
  → 배정 항목 제거
  → decline 기록 {지원자, 대상자, 시각, 사유} 추가
  → 다른 후보 추천
지원자 수행 버튼
  → 대상 환자의 해당 처방 제거
  → 수행한 지원자에게 소요시간을 귀속하고 지원 건수 +1
지원 종료
  → end=max(현재 시각, 지원 시작+5분)
  → 지원시간 및 수행 건수 기록
```

거절 사유 선택지: 휴식, 중증 환자 전담, 다른 업무.

주의: `S.done`에는 수행자별 처방 소요시간을 누적하지만, **해당 누적값 자체는 현재 화면에 표시되지 않습니다.** 지원 기록 표는 시작시간, 소요시간, 수행 건수, 거절 이력을 표시합니다. 지원 종료의 최소 소요시간 5분도 시연용 처리입니다.

### 4.8 F09 근무조 인력 적정성

```text
대상 = 담당 환자가 1명 이상인 간호사만 포함
근무조 전체 업무량 = 대상 간호사의 현재 업무량 합
인력 기준 = 대상 간호사 수 × 50분
단계:
  총 업무량 > 인력 기준: 초과
  총 업무량 > 인력 기준 × 0.8: 주의
  그 외: 적정
```

초기 상태: 환자 담당 5명, 현재 업무량 합계 256분, 인력 기준 250분 → **초과**, 3단계 알림.

원본 안내문에는 '담당 환자 1명당 50분' 기준은 협의 중이라고 적혀 있으나, **현재 실행 코드는 환자 수가 아니라 담당 환자가 있는 간호사 수 × 50분**입니다. 적용 기준의 재확인이 필요합니다.

### 4.9 F10 구역별 처방 적시성

구역(간호사 담당 role) 단위로 다음을 계산합니다.

| 지표 | 계산식 |
|---|---|
| 대기 건수 | 해당 구역의 담당 환자에게 남아 있는 `orders` 개수 |
| 최장 대기 | 해당 구역 미완료 처방별 `현재 시각 - 발생 시각`의 최댓값. 처방이 없다면 0 |
| 기준 초과 | 각 처방의 대기시간이 `dueOf` 이상인 건수 |

구역별 처방 수행률이나 전체 발생 대비 정시 완료율은 계산하지 않습니다. 현재 화면 제목은 '처방 적시성'이지만 실제로는 **미완료 처방의 대기 및 지연 현황**입니다.

### 4.11 F15 조회 권한

| 조회자 | 정보 표시 |
|---|---|
| 근무조 리더간호사 (`leader`) | 전체 간호사 상세 카드, 환자 및 처방 정보, 지원 알림 및 관리 동작 |
| 응급전문간호사 (`np`) | 전체 상세 조회 및 동일한 관리 기능. 코드상 실제 역할별 관리 권한 차이는 없음 |
| 개별 담당간호사 | 본인 상세 카드, 동료의 업무 단계 요약. 지원 알림 목록 대신 안내 문구 |
| 지원 수락 중인 간호사 | 본인 및 지원 대상 간호사의 상세 카드. 지원 대상 처방 대리 수행 가능 |

이것은 시연용 드롭다운에 의한 화면 분기이며, 실제 로그인 기반 인증이나 서버 권한 검증이 아닙니다.

### 4.12 F16 지원 우선 대상

- `prio` 토글값이 켜지면 수행 기준시간에서 10분을 차감하고 최소 5분을 적용합니다.
- 해당 간호사는 현재 `높음` 또는 직접 지원 요청 상태에서 지연 처방이 **1건 이상**이면 2단계 조건을 만족합니다. 일반 간호사는 같은 선행 조건에 더해 **2건 이상**입니다.
- 추천 지원자 후보에서는 `prio=true` 간호사를 제외합니다.
- 처음에는 박도윤 간호사만 우선 대상으로 지정되어 있습니다.

## 5. 처방별 표준 소요시간 (`CAT`)

| 분류 | 처방명 (표준 소요시간) |
|---|---|
| 높음(H) | CPR 진행(42), Central line 삽입 준비 및 보조(30), Intubation 준비 및 보조(30), 수술 전 준비(30), 시술 전 준비(CAG)(25), 수혈(PRBC)(25), A-line 삽입 준비 및 보조(20) |
| 중간(M) | 도뇨관 삽입(15), 중환자실 입원 준비(15), 정맥 항생제(10), 항생제(패혈성 쇼크)(10), 승압제 투여 시작(10), 채혈(10), 조영 검사 전 준비(10) |
| 낮음(L) | 정맥 주사(IV push)(5), 에피네프린 투여(5), 수액 교체(5), 경구약(3) |

단위는 분. 목록 중 CPR 진행, 중환자실 입원 준비, 승압제 투여 시작, 에피네프린 투여 등은 `newOrder`의 무작위 발생 후보에서 제외되지만 이벤트 시나리오에서는 생성될 수 있습니다.

## 6. 연구실에서 계획한 5개 Agent Builder Flow와 코드 대응

| 계획 Flow | 원본에서 대응되는 기능 | 입력 | 처리 | 출력 | 구현 유의사항 |
|---|---|---|---|---|---|
| Flow 1. 간호사별 업무 단계 판단 | F01, F02, 필요 시 F03 | 간호사별 환자, KTAS, NEWS, 활력주기, 미완료 처방, 수락된 지원 | 업무량 분 단위 합산, 상태 강제 조건, 임계값 분류 | 간호사별 `now`, `forecast`, `level`, `breakdown` | 이전에 논의한 '초과시간 합산'과는 다른 로직. 기준 선택 필요 |
| Flow 2. 업무 추천 알림 생성 | F04, F05, F06 | Flow 1 결과, 수행 기준 초과 건수, 급증 이벤트, 지원 요청, 우선 대상, 지원 이력 | 알림 단계 및 사유 판정, 후보 제외 및 정렬 | `alerts[]`, `recommendedNurseId` | 장시간 유지 여부는 시간 상태 저장이 필요 |
| Flow 3. 지원 기록 | F07, F08 | 배정, 수락 및 거절, 수행 완료, 종료 이벤트 | 지원 상태 변경, 수행자 귀속, 시간 및 건수 누적 | `supportLogs[]`, `activeSupports[]` | CRUD 및 이벤트 저장 성격이 강함. 지속 상태는 백엔드/DB에서 관리하고 Flow는 필요 부분에 활용하는 편이 적합 |
| Flow 4. 인력 적정성 계산 및 단계 구분 | F09 | 환자 담당 간호사별 업무량 | 업무량 합계, 인력 기준 대비 | `total`, `limit`, `status` | '간호사 1명당 50분'과 '환자 1명당 50분' 해석 확인 필요 |
| Flow 5. 구역별 처방 적시성 | F04, F10 | 구역, 처방 ID, 발생 시각, 기준시간, 미완료 여부 | 대기시간 계산, 초과 여부, 구역별 집계 | 구역별 `pendingCount`, `maxWait`, `overdueCount` | 정시 완료율이 아니라 현재 대기 및 지연 현황임을 명시 |

권장 아키텍처: React는 화면 표시 및 사용자 조작, FastAPI 등 백엔드는 시연 시간과 주문/지원 상태 관리, Agent Builder Flow는 계산 및 규칙 판단을 수행하는 방식으로 역할을 구분합니다. **이 항목은 소스에 구현되어 있는 내용이 아니라 향후 개발 제안**입니다.

## 7. 구현 시 주의할 사항

1. **업무량과 초과시간은 별도 지표**입니다. 현재 업무량은 예정 업무 소요시간 합계이고 지연 처방은 개수로 관리합니다. '초과시간 합계를 업무량으로 사용'하려면 명시적으로 규칙을 변경해야 합니다.
2. **50분 경계 차이**: `LV`에서 높음은 50분 **초과**이며, 50분 정확히는 보통입니다.
3. **인력 기준 불일치**: 현재 실행 코드는 담당 환자가 있는 간호사 수 × 50분을 사용합니다. 안내문에 언급된 환자당 50분 개념과 다릅니다.
4. **NEWS 가산과 NEWS 상승**: 5점 이상에 따른 관찰시간 가산은 현재 업무량에 들어가고, 위험단계 상승 5분 추가분은 1시간 뒤 예측값에만 들어갑니다. 환자 악화 이벤트는 두 값과 별개로 높음 상태를 강제합니다.
5. **지원 부하 감소**: 수락된 지원자 1명마다 현재 및 예측 업무량을 일정 비율 줄이는 시연 규칙입니다. 실제 수행된 업무량이나 환자 재배정량으로 검증되지 않았습니다.
6. **권한은 시연 전용**: 드롭다운에서 사용자를 변경할 뿐 인증이나 권한 확인 API는 존재하지 않습니다.
7. **경진대회 데모의 범위**: 로직은 재현할 수 있으나 임상적 타당성, AMIS 접근, 개인정보 처리, 보안성, 운영 적합성은 별도 검토가 필요합니다.
