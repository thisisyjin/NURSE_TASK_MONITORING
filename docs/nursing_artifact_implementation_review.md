# 최신 Artifact React 재구현 검토

기준은 `nursing_artifact_reference/app.js`의 실행 동작이다. `docs/nursing_artifact_function_spec.md`는 수정하지 않았고, 원본과 설명이 같은 부분은 원본대로 구현했다. 이 문서는 다음 간호부 검토에서 남길 기능과 뺄 기능을 고르기 위한 자료다. 이번 단계에서 기능을 삭제하지는 않았다.

화면은 `http://localhost:5174/`에서 09:00 초기값, 처방 수행, 지원 배정과 수락, 간호사 화면 분기, 초기화, 첫 간호요구 급증, CPCR 발생을 확인했다. 기본 테마는 라이트 모드다.

## 1. 현재 구현 기능

| ID | 기능명 | 구현 상태 | 화면 위치 | 주요 로직 |
|---|---|---|---|---|
| F01 | 간호사별 현재 업무량 | 구현 | 간호사 카드 | `loadOf`. 관찰 + 활력 + 미완료 처방 소요시간. 수락된 지원자만 감산 |
| F02 | 업무 단계 | 구현 | 카드 배지, 막대 색 | `levelOf`, `minutesLevel`. 30 미만 여유, 30 이상 50 이하 보통, 50 초과 높음. 급증 이벤트면 즉시 높음 |
| F03 | 1시간 뒤 예측 | 구현 | 카드 막대의 옅은 부분 | 60분 내 예정 처방 + NEWS 위험 단계 상승당 5분. 같은 감산 비율 |
| F04 | 수행 기준 초과 | 구현 | 처방 행, 초과 건수 칩 | `dueOf`. 소요시간과 수행 기준은 별도 필드 |
| F05 | 지원 알림 | 구현 | 우측 지원 알림 | `buildAlerts`. 예측, 1~4단계, 긴급 |
| F06 | 지원자 추천 | 구현 | 알림의 배정 버튼 | `recommendNurse`. 여유 우선, 같은 단계에서는 업무량이 적은 순 |
| F07 | 배정, 수락, 거절 | 구현 | 알림 버튼, 지원자 카드 | 수락 전 감산 없음. 거절 사유 3개 |
| F08 | 지원 및 수행 기록 | 구현 | 우측 지원 기록 | 수행자 귀속, 수락 대기, 진행 중, 종료 분, 거절 행 |
| F09 | 인력 적정성 | 구현 | 우측 인력 적정성 | 환자 담당 간호사 수 × 50분. 초과, 주의(80%), 적정 |
| F10 | 구역별 처방 적시성 | 구현 | 우측 처방 적시성 | 미완료 대기 건수, 최장 대기, 기준 초과 건수 |
| F11 | 시간 진행, 처방 발생 | 구현 | 상단 버튼 | `stepMinutes`, `spawnOrder`. 난수 포함 |
| F12 | 간호요구 급증 | 구현 | 상단 버튼, 카드 상황 종료 | 첫 클릭은 5-02 고정. 이후 클릭은 난수 |
| F13 | CPCR | 구현 | CPCR 발생, 긴급 알림 | 09:30 자동 또는 버튼. ROSC, 안정화, CPR 팀 |
| F14 | A-plus | 구현 | 4단계 알림 버튼 | 새 카드. CPR 팀 환자가 있으면 임시 인계 |
| F15 | 조회 화면 | 구현 | 보기 선택 | 리더, 응급전문간호사는 전체. 개인은 본인 상세와 동료 단계. 수락 중이면 대상 상세 |
| F16 | 지원 우선 대상 | 구현 | 카드 버튼, 배지 | 수행 기준 10분 단축, 최소 5분. 추천 후보에서 제외 |
| F17 | 초기화, 자동 진행 | 구현 | 상단 버튼 | 2초마다 시연 5분. 초기화는 09:00과 타이머 중지 |
| F18 | 처방 분류 기준 | 구현 | 우측 표 | `ORDER_CATALOG` |

09:00 확인값: 김서연 127 높음, 박도윤 31 보통, 이하은 53 높음, 최민준 11 여유, 정유나 34 보통, 한지호 환자 없음 여유. 근무조 256/250 초과. 예측은 167, 41, 63, 11, 44.

## 2. 원본과 React 구현 비교

| 구분 | 최신 Artifact | 현재 React 구현 | 차이점 |
|---|---|---|---|
| 화면 뼈대 | 헤더, 조작 바, 카드, 알림, 기록, 인력, 적시성, 분류표 | 같은 순서로 렌더 | 연결 문장의 가운데점은 쉼표로 바꿨다. 처방명 안의 가운데점은 원본 이름 그대로다 |
| 테마 | 라이트 기본, 시스템 다크면 어두워질 수 있음 | `data-theme="light"`로 라이트 고정 | 시연 화면이 시스템 설정에 따라 어두워지지 않는다 |
| 초기 데이터 | `init()`의 6명, 환자, 처방 | `createInitialArtifactState` | 09:00 숫자 일치 |
| 업무량 | `loadOf` | `src/domain/artifact/rules.ts` | 같은 식 |
| 단계 경계 | 50분 정확히는 보통 | `minutesLevel` | 같은 식. 테스트로 29, 30, 50, 51 확인 |
| 인력 기준 | 환자 담당 간호사 수 × 50 | 같은 식 | 이전 React는 담당 환자 수 × 50이었다. 이번 화면은 원본 실행 코드를 따른다. 안내문도 환자 1명당 50분은 협의 중이라고 남겼다 |
| 지원 감산 | 수락 후 `max(0.35, 1-0.4k)` | 같은 식 | 수락 전 127, 수락 후 76을 테스트로 확인. 화면에서는 수혈 수행 후 102가 수락 뒤 61이 되는 것까지 확인 |
| 알림 | `alerts()` | `buildAlerts` | 초기 3건(3단계, 김서연 2단계, 이하은 1단계) |
| 추천 | 한지호 | 같은 정렬 | 거절 후 최민준 |
| 조회 | 드롭다운 | 같은 분기 | 로그인 없음 |
| 난수 | `Math.random` | 같은 확률. 테스트만 고정 난수 | +15분과 추가 급증, 무작위 처방은 실행마다 달라질 수 있다 |
| F2 API | 없음 | 코드는 남아 있고 화면에는 패널을 올리지 않음 | 기존 F2 샘플의 09:00은 136, 34, 60, 11, 합계 241이다. 이번 Artifact와 다른 데이터라 연결하지 않았다 |
| 이전 화면의 보조 패널 | 없음 | 근무 운영 요약, 이벤트 기록은 화면에서 뺌 | 파일은 지우지 않았다. 최신 원본에 없는 패널이다 |

## 3. 간소화 검토 대상

삭제하지 않았다. 발표용으로 빼거나 접을 후보만 적는다.

- CPCR 전 과정(ROSC, 안정화, CPR 팀, A-plus 임시 인계). 버튼과 경과 규칙이 길고 09:30에 자동으로도 시작한다.
- 자동 진행과 무작위 처방, 시간 진행 중 NEWS 난수. 같은 시연을 반복하기 어렵다.
- 두 번째 이후 간호요구 급증의 무작위 대상. 첫 클릭(5-02)만 고정이다.
- 1시간 뒤 예측 막대와 예측 알림. AI 예측이 아니라는 설명이 필요하다.
- 처방 분류 기준표. 시연 중 조작은 없다.
- 지원 우선 대상의 10분 단축, 거절 사유 3개, 상황 종료.
- 응급전문간호사 보기. 코드상 리더와 권한이 같다.
- 4단계 알림과 A-plus. 3단계가 30분 지속되거나 CPR 팀이 투입될 때 생긴다.
- 개인 간호사 화면의 동료 단계만 보기. 발표에서 리더 화면만 쓸 거면 접을 수 있다.

## 4. Agent Builder 연동 후보

이번 빌드는 다섯 기능을 화면 안 순수 함수로만 호출한다. Flow나 API는 붙이지 않았다. 나중에 함수 호출만 바꾸면 된다.

| Flow | 현재 함수 | 입력 | 출력 |
|---|---|---|---|
| 1. 업무 단계 | `loadOf`, `levelOf` | 간호사, 환자 KTAS, NEWS, 활력 주기, 미완료 처방, 수락된 지원 수, 열린 급증 이벤트 | `now`, `base`, `vsl`, `pend`, `fc`, `level` |
| 2. 추천 알림 | `dueOf`, `buildAlerts`, `recommendNurse` | Flow 1 결과, 대기시간, 우선 대상, 지원 필요 표시, 높음 시작 시각, 거절 이력 | `alerts[]`, 추천 간호사 id |
| 3. 지원 기록 | `assignSupport`, `acceptSupport`, `declineSupport`, `completeOrder`, `endSupport` | 배정, 수락, 거절, 수행, 종료 이벤트 | `supports[]`, `decline[]`, `done` |
| 4. 인력 적정성 | `capacityOf` | 환자 담당 간호사의 현재 업무량 | `total`, `limit`, `n`, `level` |
| 5. 구역 적시성 | `zoneTimeliness` | 구역, 미완료 처방, 발생 시각, 수행 기준 | `pendingCount`, `maxWaitMin`, `overdueCount` |

상태 자체(`t`, 환자, 처방, 지원, CPR)는 화면 스토어가 갖고, 위 함수는 그 상태를 읽어 결과만 돌려준다.

## 5. 미확정 판단 기준

간호부 확인이 필요하다. 모두 시연용이며 이번 코드는 원본 숫자를 유지했다.

- 관찰 부하: KTAS 1=20, 2=15, 3=10, 4=5, 5=3. NEWS 7 이상 +10, 5~6 +5, 그 외 0. 이전 HTML 시연표와 다르다.
- 활력: 회당 3분, `round(60/주기*3)`. 환자마다 반올림한다.
- 단계: 50분 이하는 보통, 50분 초과만 높음. 급증은 업무량과 무관하게 높음.
- 수행 기준: 기본 30분. 패혈성 쇼크 항생제 60, CPR과 에피네프린 5, Intubation 10. 우선 대상은 10분 단축, 최소 5분. 표준 소요시간과 다른 값이다.
- 지원 감산: 수락 1명당 40% 감소, 최저 35%. 실제 분담량이 아니다.
- 인력: 실행 코드는 환자 담당 간호사 수 × 50이다. 화면 안내와 이전 프로젝트 결정은 환자 수 × 50이다. 이번 구현은 실행 코드를 따랐다.
- 주의 구간은 기준의 80% 초과. 원본에만 있는 시연 규칙이다.
- NEWS 화살표는 위험 단계가 올라갈 때만. 상승 5분은 예측에만 더한다.
- 이전 F2 v3 샘플은 이번 초기 데이터와 맞지 않는다. 연동 전에 입력과 기대값을 다시 맞춰야 한다.

## 6. 검증

- `npm test`: 3개 파일, 25개 통과. 초기 업무량, 경계값, 감산, 거절 후 재추천, 급증, 고정 난수의 +15분 두 번과 09:30 CPCR, 초기화.
- `npm run build`: 통과. Node 20.18은 Vite가 20.19 이상을 권장한다는 경고만 있다.
- 브라우저: 09:00 숫자, 수혈 수행 후 102분과 인력 231/250 주의, 배정 직후 감산 없음, 한지호 화면 수락 후 61분과 대상 처방의 대리 수행 버튼, 초기화 후 127분과 알림 3건, 첫 급증 19분과 높음 사유, CPCR 긴급 알림과 팀 배정 버튼.

자동 진행 버튼과 A-plus 인계는 코드와 단위 테스트 경로에 있고, 이번 브라우저 확인에서는 누르지 않았다.
