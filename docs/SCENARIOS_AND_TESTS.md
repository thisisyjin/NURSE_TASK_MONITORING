# 시연 시나리오 및 검증 체크리스트

기존 시연 PDF 2~8페이지의 순서를 중심으로 작성했다. **정확한 전환 데이터는 HTML 내부 코드를 열어 확인하고, 변경된 간호부 답변을 우선 적용**한다.

## 1. 공통 원칙

- 실제 시각이 아니라 가상 시각을 사용한다. 시작은 **09:00**이다.
- 같은 입력 상태와 같은 시나리오 이벤트는 항상 같은 결과를 출력한다.
- 초기화는 데이터와 알림, 지원 기록, 시연시간을 모두 시작 상태로 되돌린다.
- 외부 API가 없어도 끝까지 실행 가능해야 한다.
- 가상 상태를 바꾸는 버튼은 수행 결과가 현황판에 반영되어야 한다.

## 2. 기본 시연 흐름

### S01. 책임간호사 최초 화면 (PDF p.2)

**사용자 행동:** 첫 진입 또는 `초기화` 클릭

**예상 화면:**

- 09:00, D 근무, 책임간호사 보기
- 환자 담당 간호사 카드 4개 및 별도 역할 카드 2개
- 가상 환자별 KTAS, NEWS, 활력 주기와 수행 대기 처방
- 우측 지원 알림, 인력 적정성, 구역별 처방 적시성, 지원 기록, 분류 기준
- 현재 업무량이 `관찰 + 활력 + 대기 처방 예상시간`과 일치
- 변경된 인력 기준인 `담당 환자 수 × 50분`이 반영되어 있음

**검증 포인트:** 이전 `4명 × 50분` 기준이 남아 있지 않아야 한다. 따라서 원본과 지원 단계 알림 건수가 달라질 수 있다.

### S02. 지원 알림 및 지원 배정 (PDF p.3)

**사용자 행동:** 지원 알림 선택, 추천 후보 확인, 지원 배정

**예상 화면:**

- 지원 대상 간호사 및 추천 후보와 추천 이유 표시
- 지원 불가 간호사는 추천에서 제외
- 책임간호사가 후보를 수동으로 변경할 수 있음
- 배정 알림이 지원 간호사에게 전달됨
- 수락 또는 거절(사유) 동작 후 상태 반영

**검증 포인트:** 구 PDF의 한지호 → 김서연 지원 사례를 참고하되, 최신 답변의 수락 및 거절 절차를 생략하지 않는다.

### S03. 지원 간호사의 처방 수행 (PDF p.4)

**사용자 행동:** 배정된 지원 간호사로 김서연의 대기 처방 2건을 수행하는 시연

**예상 화면:**

- 해당 두 처방이 수행 완료 상태가 되고 미완료 목록에서 제외
- 담당 간호사의 남은 처방 예상 업무량 감소
- 실제 수행 간호사 ID가 지원자로 저장
- 지원 이력의 `수행 건수`가 2건으로 갱신

**검증 포인트:** 완료한 처방을 다른 수행자가 다시 수행할 수 없어야 한다. 지원자의 남은 업무량에 이미 완료된 업무 시간을 다시 더하지 않는다.

### S04. 지원 종료 (PDF p.5)

**사용자 행동:** 09:15에 지원 종료

**예상 화면:**

- 시작 09:00, 종료 09:15, 지원 시간 15분
- 수행 건수 2건
- 진행 중 상태에서 종료 기록으로 변경

**검증 포인트:** 09:15에 종료했는데 시작시각이 없거나 지원 경과시간이 음수가 되는 일이 없어야 한다.

### S05. 09:45 시간 진행 (PDF p.6)

**사용자 행동:** 09:15에서 09:45로 시간 진행 또는 원본 HTML의 시나리오 조작 실행

**예상 화면:**

- 가상 시각 09:45
- 예정 처방의 예정 시각 도래 여부 반영
- 시연용 신규 처방 및 NEWS 변화 이벤트 반영
- 대기 경과시간, 처방 초과, 업무량, 지원 알림 갱신
- 인력 적정성도 최신 데이터 및 최신 기준으로 갱신

**검증 포인트:** 아직 예정시각이 되지 않은 처방을 지연 처방으로 잘못 집계하면 안 된다.

### S06. 환자 상태 악화 / 간호요구 급증 (PDF p.7)

**사용자 행동:** 원본 HTML의 간호요구 급증 시나리오 실행. 시연 PDF에는 D-02 사례가 등장

**예상 화면:**

- 해당 환자 담당 간호사의 단계 즉시 `높음` 표시
- `환자 악화` 등 사유를 화면에 표시
- 지원 알림 및 추천 흐름 동작

**검증 포인트:** NEWS나 KTAS별 관찰시간 계산식이 없어도 `악화 이벤트`로 이 시나리오를 재현할 수 있어야 한다. 임의의 임상 수치를 창작하지 않는다.

### S07. 일반 간호사 보기 (PDF p.8)

**사용자 행동:** 화면 보기 전환 후 박도윤 등 일반 간호사 선택

**예상 화면:**

- 본인 환자 및 처방 상세만 표시
- 다른 간호사 카드에는 업무량 단계 등 허용 정보만 표시
- 우선 대상 지정과 관리자용 지원 알림은 숨김
- 자신에게 배정된 지원 업무가 있으면 수락 및 거절 UI에 접근 가능

**검증 포인트:** 단순 CSS로 화면 바깥에 놓거나 투명도를 조절하는 방식이 아니라, 허용되지 않는 상세 UI 자체를 렌더링하지 않는 방식 권장. 이 시연은 실제 접근 통제 시스템은 아님.

### S08. 초기화 및 다시 시연

**사용자 행동:** 초기화 후 S01부터 다시 진행

**예상 화면:**

- 초기 가상 시각 09:00
- 지원 기록, 수행 완료, 알림, 추가 처방 및 상태 악화 이벤트 모두 초기 상태로 복귀
- 같은 시연을 반복해도 결과가 동일

## 3. 단위 테스트 대상

| 테스트 | 입력 및 상황 | 기대 결과 |
| --- | --- | --- |
| 업무량 합산 | 관찰 40, 활력 12, 처방 합계 83 | 총 135분 |
| 처방 수행 | 예상 25분짜리 미완료 처방을 완료 | 미완료 처방 총합이 정확히 25분 감소 |
| 처방 경과시간 | 발생 후 40분 경과, 목표 30분 | 경과 40분 및 초과 표시 |
| 수행시간 구별 | 처방 수행 25분, 경과 대기 40분 | 대기 처방 업무량에는 25분만 포함 |
| 예정 처방 | 예정시간 09:30, 현재 09:15 | 지연으로 표시하지 않음 |
| 구역 초과 건수 | 같은 구역에 초과 처방 2건 | 2건 표시. 카드와 우측 집계 일치 |
| NEWS 표시 | 이전 위험 단계 2~4, 현재 5~6 | 상승 화살표 표시 |
| NEWS 표시 반례 | 이전 NEWS 5, 현재 6 | 같은 위험 단계이므로 상승 화살표 없음 |
| 인력 기준 | 담당 환자 9명, 환자당 50분 | 비교 기준 450분 (단순 테스트 케이스) |
| 예전 기준 금지 | 담당 간호사 4명, 환자 9명 | 200분을 기준으로 사용하지 않음 |
| 악화 처리 | D-02 악화 이벤트 | 해당 간호사 단계 즉시 높음 |
| 지원 불가 | 지원 후보가 휴식 중 | 추천에서 제외 |
| 지원자 변경 | 책임간호사가 다른 지원자 선택 | 선택한 지원자로 배정 |
| 지원 기록 | 09:00 시작, 09:15 종료, 2건 수행 | 15분, 2건 기록 |
| 중복 수행 | 같은 처방에 수행 버튼 두 번 | 1회만 완료 처리 및 집계 |
| 중복 이벤트 | 같은 시나리오 이벤트 두 번 발생 | 처방 또는 기록 중복 생성 금지 |
| 화면 제한 | 일반 간호사 보기 | 동료 상세 환자 및 관리자 알림 미노출 |
| 초기화 | 처방 수행, 지원 배정, 시간 진행 후 Reset | 처음 시드 상태와 동일 |

## 4. 통합 테스트: Flow Mock 계약

- [ ] F1 처방 분류 결과를 변경하면 F2 업무량에 반영된다.
- [ ] 처방을 완료하면 F2의 대기 처방 시간과 F3의 미완료 초과 건수가 감소한다.
- [ ] F2 업무량 또는 F3 처방 지연이 변경되면 F4 지원 단계가 재평가된다.
- [ ] 현재 시나리오가 달라져도 직전 비동기 계산 응답이 최신 화면을 덮지 않는다.
- [ ] API 모드가 Mock인 동안 외부 서버 호출은 발생하지 않는다.
- [ ] 실제 Flow가 없을 때도 화면은 시연 가능하다.
- [ ] 실제 Flow 오류가 발생하면 오류를 표시하며, Mock 결과를 실제 Flow의 결과라고 속이지 않는다.

## 5. UI 검증

- 원본 HTML 대비 레이아웃 및 컴포넌트 구성 비교
- 데스크톱 너비에서 2열 간호사 카드와 우측 패널 가독성
- 좁은 화면에서 가로 넘침 및 버튼 클릭 가능 여부
- `높음`, `보통`, `여유`는 색뿐 아니라 문자로도 구분
- 단위 표기 (`분`, `건`, `구역`, `KTAS`, `NEWS`) 일관성
- 사용자 클릭 후 즉시 피드백 제공
- 수락, 거절, 종료 버튼의 허용 상태 검증
- 지원자 후보가 없을 때 빈 상태 설명
- 계산 로딩과 실패 상태 처리
- 잘못된 샘플 값(음수 시간, 존재하지 않는 담당 간호사 ID 등) 감지

## 6. 마감이 촉박할 때 구현 우선순위

| 순서 | 반드시 먼저 완성할 기능 | 미뤄도 되는 세부 항목 |
| --- | --- | --- |
| P0 | 기존 HTML에 가까운 책임간호사 현황판, 환자 카드, Mock 데이터 | 새로운 디자인 체계 |
| P0 | 업무량 합계, 처방 대기/초과, 수행 버튼, 리셋 | 장기 통계 |
| P0 | 지원 알림, 배정, 수행 기록, 09:00→09:15→09:45 | 자동 반복 시연의 고급 설정 |
| P1 | 일반 간호사 보기, 우선 대상 UI 권한, 수락 및 거절 | 실제 병원 인증 |
| P1 | F1~F4 서비스 인터페이스와 Mock 구현 | 실제 Agent Builder Flow 구현 |
| P2 | 브라우저 저장, 고급 필터, 추가 시나리오 | 운영용 DB 및 외부 연동 |

**P0와 P1 항목을 중심으로 React 시연을 끝까지 완성한다.** AI 예측 및 AMIS 통합은 이번 마감에 맞추려고 급하게 추가하지 않는다.
