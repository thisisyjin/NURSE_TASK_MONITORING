# V3 화면 구조 제안

## V2가 긴 이유

V2는 기능과 상태 전이는 갖췄지만, 화면은 간호사 카드 안에 환자, 등록번호, NEWS, 처방, 수행, 확인중을 기본으로 펼쳤다. 카드 6개가 세로로 이어지고, 지원이 필요한 간호사마다 같은 추천 카드를 크게 반복했다. 글자 크기와 굵기가 비슷해 127분, 높음, 한지호가 한눈에 들어오지 않았다.

## 이번 구조

첫 화면은 상태와 추천만 둔다. 환자와 처방은 간호사 카드를 눌렀을 때 오른쪽 드로어에서 연다. 드로어는 카드 높이를 늘리지 않는다.

```text
헤더: 제목, 09:00, 현재 화면, +15분, 시연 제어
요약 줄: 높음 N명, 지원 필요 N건, 지원 진행 N건, 업무량 / 인력 기준
본문 왼쪽 약 62%: 간호사 요약 카드 3열 2행
본문 오른쪽 약 38%: 지원 필요 목록(행) + 선택된 1건의 추천 패널
하단 한 줄: 구역별 대기, 최근 지원 2~3건, 인력 기준 설명
```

본문 최대 폭은 1600px로 늘린다. 1280px에 가두지 않는다.

## 컴포넌트

| 영역 | 컴포넌트 | 상태 |
|---|---|---|
| 요약 카드 | `NurseCard`, `NurseGrid` | 기존 `loadOf`, `levelOf`, `nurseQueue`만 표시 |
| 환자 상세 | `NurseDetailDrawer` | 카드 선택 시에만. 수행, 확인중, 대기로 복귀, 지원 필요는 여기 |
| 지원 매칭 | `SupportAlertPanel` | 목록에서 한 명을 고르면 패널 내용만 바뀜 |
| 간호사 응답 | `IncomingRequestBanner` | 해당 간호사 화면 상단. 수락과 거절 |
| 보조 | `ZoneTimelinessPanel`, `SupportHistoryPanel`, `StaffingPanel` | 하단 한 줄. 표와 전체 기록은 펼침 또는 모달 |

선택 중인 지원 대상과 열린 간호사 상세는 화면 상태다. 업무량과 지원 기록의 Zustand 상태는 바꾸지 않는다.

## 추천 패널

```text
지원 필요  [김서연 높음] [이하은 높음]

지원 대상              추천 1순위
김서연                 한지호
높음, 127분      →     여유, 0분
[여유] [업무량 0분] [현재 지원 없음]

다른 후보 선택 [드롭다운]
[한지호에게 지원 요청]

추천 → 배정 요청 → 지원 진행 → 완료
```

수락된 지원은 알림 목록에서 빠지던 기존 계산을 유지한다. 화면 목록에는 진행 중인 대상을 다시 올려, 배정 뒤에도 같은 패널에서 단계가 보이게 한다. 새 업무량 숫자는 만들지 않는다.

## 역할 화면

개별 간호사는 동료 환자 상세를 열 수 없다. 본인과, 수락한 지원 대상만 드로어가 열린다. 받은 요청은 페이지 상단 배너에서 수락하거나 거절한다.

## 글자

Pretendard를 유지한다. 제목 20~22px, 업무량 숫자 30px, 본문 14px, 보조 설명 13px. 10~11px는 쓰지 않는다. 버튼 높이는 36px 전후로 맞춘다.
