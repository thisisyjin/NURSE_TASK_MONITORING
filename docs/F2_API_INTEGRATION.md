# F2 v3 API 연동

기본 화면은 계속 Mock이다. F2 API는 우측 `F2 API 연결` 패널을 열었을 때만 사용한다.

## 환경

- 브라우저 경로: `/f2-api/api/v1/run/0cbe3a7e-2d2c-498f-bc6d-95703ce59380`
- 개발 서버가 `http://192.168.45.149:3001`으로 전달한다. `vite.config.ts`의 프록시다.
- API 키는 `.env.local`의 `F2_API_KEY`에 둔다. 이 파일은 git에 올리지 않는다. 패널에 키를 입력하면 그 값이 요청 헤더에 실리고, 비워 두면 개발 서버가 `.env.local` 키를 붙인다.
- `172.24.180.159:5174`에서 열면 브라우저는 같은 주소의 `/f2-api`만 호출한다. Agent Builder가 그 Origin을 CORS로 허용하지 않아도 된다.
- `mode: 'no-cors'`는 쓰지 않는다. 별도 백엔드는 없다.

## 실행

```bash
npm install
npm run dev
```

1. 개발 서버를 다시 실행한 뒤 `http://localhost:5173` 또는 `http://172.24.180.159:5174`로 연다. 포트는 터미널에 나온 값을 쓴다.
2. `F2 API 연결`을 펼친다. `.env.local`에 키가 있으면 입력란은 비워도 된다.
3. `09:00 샘플 호출`은 `samples/f2-input-0900.json`만 보낸다. 카드를 바꾸지 않는다. 성공하면 간호사 네 명과 근무조 241분, `calculation_version`이 `html_demo_f2_v3_batch`인지 본다.
4. `현재 상태 API`는 Zustand의 현재 환자를 F2 입력으로 바꿔 카드의 관찰, 활력, 대기 처방, 합계, 단계에 반영한다.
5. `Mock`을 누르면 다시 로컬 계산만 쓴다.

## 이번 호출에서 확인한 것

2026-11-19에 `samples/f2-input-0900.json`을 실제 Flow로 POST했다. HTTP 200이고 `calculation_version`은 `html_demo_f2_v3_batch`였다. 결과 JSON 문자열은 `outputs[0].outputs[0].results.message.text`에 있었다. 같은 문자열이 artifacts와 messages에도 반복된다.

| 간호사 | 합계 | 단계 |
| --- | ---: | --- |
| 김서연 | 136 | 높음 |
| 박도윤 | 34 | 보통 |
| 이하은 | 60 | 높음 |
| 최민준 | 11 | 여유 |

근무조 합계는 241분으로 Mock 09:00과 같다. 브라우저 화면에서 버튼을 눌러 카드가 바뀌는 것까지는 이 호출로 확인하지 않았다. 개발 서버를 다시 띄운 뒤 패널의 `09:00 샘플 호출`로 같은 숫자를 보면 된다.

## 요청

```json
{
  "input_type": "chat",
  "output_type": "chat",
  "input_value": "{\"scenario\":{\"id\":\"initial_0900\",\"clock\":\"09:00\"},\"nurses\":[...]}"
}
```

`input_value`는 스냅샷을 `JSON.stringify`한 문자열이다. `session_id`는 보내지 않는다.

현재 화면을 보낼 때의 09:00 예시는 다음과 같다. 처방 ID는 스토어 ID를 그대로 쓴다.

```json
{
  "scenario": { "id": "ui_540", "clock": "09:00" },
  "nurses": [
    {
      "id": "n1",
      "name": "김서연",
      "patients": [
        {
          "id": "A-01",
          "ktas": 2,
          "news": 6,
          "vital_interval_minutes": 30,
          "acute_deterioration": false,
          "orders": [
            { "id": "a01-prbc", "name": "수혈(PRBC)", "status": "pending", "estimated_minutes": 25 }
          ]
        }
      ]
    }
  ]
}
```

정유나, 한지호는 넣지 않는다. 관찰 분과 활력 분은 넣지 않는다. 예정 시각 전 처방은 `scheduled`, 완료는 `completed`다. 시각이 되면 기존 시연 로직이 `pending`으로 바꾼 뒤 다시 호출한다.

## 결과 예시

`samples/f2-expected-0900.json` 기준이다. 성공 응답이 이 모양이면 카드에 이렇게 들어간다.

| 간호사 | 관찰 | 활력 | 대기 처방 | 합계 | 단계 |
| --- | ---: | ---: | ---: | ---: | --- |
| 김서연 | 41 | 12 | 83 | 136 | 높음 |
| 박도윤 | 15 | 4 | 15 | 34 | 보통 |
| 이하은 | 26 | 9 | 25 | 60 | 높음 |
| 최민준 | 6 | 2 | 3 | 11 | 여유 |

근무조 합계는 241분이다. Mock 09:00과 같은 식이다. 1시간 뒤 164분 같은 시연값은 F2가 바꾸지 않는다.

독립 샘플의 기대값은 `F2_TEST_PLAN.md`에 있다. 화면에서 처방 수행과 급증이 같이 일어나면 그 숫자와 달라진다. 화면 숫자를 샘플 값으로 덮어쓰지 않는다.

## 범위

F2가 바꾸는 것: 담당 간호사 네 명의 현재 업무량과 단계, 그 합으로 다시 계산되는 근무조 업무량 합계.

그대로 두는 것: 지연과 초과, 지원 알림과 추천, 배정, 수락, 거절, 종료, 기록, 역할 카드, 1시간 뒤 값, 인력 적정 판정 규칙.

API가 실패하면 카드는 Mock 숫자를 유지하고, 배너와 패널에 오류와 `Mock 사용 중`을 같이 보여 준다. HTTP 200이어도 본문이 `{ "error": "..." }`이거나 `calculation_version`이 `html_demo_f2_v3_batch`가 아니면 실패다.

## 남은 문제

- 09:00 샘플의 HTTP 결과는 확인했다. 브라우저에서 `현재 상태 API`를 눌러 카드가 바뀌는 동작은 개발 서버를 다시 실행한 뒤 보면 된다.
- Agent Builder 자체는 `http://172.24.180.159:5174` Origin을 CORS로 돌려주지 않았다. 화면은 그 주소의 `/f2-api`로만 호출하므로, 개발 서버 프록시가 켜져 있으면 그 Origin에서도 된다.
- 패널에 키를 직접 입력하면 브라우저 요청에 키가 보인다. 비워 두면 개발 서버만 키를 붙인다.
