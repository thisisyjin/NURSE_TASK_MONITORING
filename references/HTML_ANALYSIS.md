분석 기준일은 2026-11-18이다. 화면 구조와 숫자의 1차 근거는 `references/[데모] 간호업무량_지원_현황판.html`이다. 시연 PDF 2~8페이지는 이미지 중심이라 추출 가능한 문장이 짧고, 버튼과 상태 전이는 HTML 스크립트를 기준으로 적었다.

이번 패키지에서 확인한 자료:

## 1. 화면 구조와 주요 UI 요소

한 페이지 현황판이다. 라우트 분기는 없다. 최대 폭 1280px, 본문은 `1fr + 330px`, 카드는 2열이다. 980px 이하에서 우측 패널이 아래로 내려가고, 640px 이하에서 카드는 1열이 된다.

### 1.1. 상단

- 제목: 간호업무량 지원 현황판
- 부제: 응급실 시범, D 근무, 가상 데이터 시연
- 시연 시각: `09:00`부터. 실제 시계와 분리되어 있다.
- 보기 선택: `근무 책임간호사 (전체)`와 간호사 6명
- 버튼: `+15분 진행`, `자동 진행`, `처방 발생`, `간호요구 급증`, `초기화`
- 범례: 여유 30분 미만, 보통 30분 이상 50분 이하, 높음 50분 초과. 막대의 옅은 구간은 1시간 뒤 값

자동 진행은 2초마다 5분 진행하고, 시드 난수로 약 25% 확률의 임의 처방을 추가한다. 다시 누르면 멈춘다.

### 1.2. 간호사 카드

환자 담당 4명과 역할 카드 2명이다.

| id | 이름 | 구분 | 초기 메모 |
| --- | --- | --- | --- |
| n1 | 김서연 | 1구역 | 환자 3명 |
| n2 | 박도윤 | 2구역 | 지원 우선 대상, 프리셉터 김서연 |
| n3 | 이하은 | 3구역 | 환자 2명 |
| n4 | 최민준 | 4구역 | 환자 2명 |
| n5 | 정유나 | Pre-T | 역할 기본 단계 보통. 환자 카드 없음 |
| n6 | 한지호 | 물품관리 | 역할 기본 단계 여유. 환자 카드 없음 |

환자 담당 카드의 상세(책임간호사 또는 본인):

- 이름, 구역, 담당 환자 수, 이번 근무 수행 분
- 단계 배지
- 현재 업무량, 관찰, 활력, 대기 처방, 1시간 뒤 값, 기준선 눈금이 있는 막대
- 태그: 지원 우선 대상, 지원 필요, 지원 받는 중, 지원 중, 간호요구 급증, 수행 기준 초과 건수
- 환자 블록: 코드, KTAS, 활력 주기, NEWS, 대기 처방, 예정 처방
- 처방 행: 이름, 예상 수행시간, 대기 경과, 기준 시간, `수행` 버튼. 지원 중이면 `지원자명 수행` 버튼
- 카드 하단: `지원 필요`, 책임간호사 전용 `우선 대상 지정`, `지원 종료`, `급증 상황 해제`

역할 카드는 업무량 숫자를 보여 주지 않는다. 배지와 역할명만 있다. 다른 사람이 보면 "처방 기반 산출 대상이 아닌 역할입니다."가 나온다.

동료 보기에서는 환자, 처방, 분 단위 업무량을 그리지 않고 단계와 짧은 안내만 남긴다.

### 1.3. 우측 패널

1. 지원 알림. 책임간호사만 내용이 보인다.
2. 지원 기록. 지원자, 대상, 시작, 경과 시간, 수행 건수, 종료 버튼
3. 인력 적정성. 근무조 업무량 / 인력 기준, 막대, 적정, 주의, 초과
4. 처방 적시성. 구역, 대기 건수, 최장 대기, 기준 초과
5. 근무 운영 요약. 알림 건수, 배정 건수, 알림에서 배정까지 평균, 수행분 평균 대기, 기준 초과 후 수행, 누적 지원 시간. 개인 순위는 없다.
6. 처방 분류 기준. 규칙 9행
7. 이벤트 기록. 책임간호사만

하단 주석은 가상 데이터, 시연용 30분과 50분, 활력 회당 3분, 일반 처방 30분, 패혈성 쇼크 항생제 60분, 우선 대상 10분, 인력 기준을 설명한다.

### 1.4. 색

여유 `#2f8a57`, 보통 `#b07a12`, 높음 `#c0362c`, 브랜드 `#0e5b6e`. 단계 이름은 색만으로 구분하지 않고 배지 문구로도 표시한다.

## 2. 데이터 모델과 이벤트

### 2.3. HTML 내부 계산

관찰 분, 시연용 표:

- KTAS 1=25, 2=15, 3=8, 4=4, 5=2
- NEWS 7 이상 +12, 5 이상 +7, 3 이상 +3, 그 외 0
- 급증 플래그가 있으면 관찰에 20분을 더한다.

활력 분: `round(60 / 주기분 * 3)`.

대기 처방 분: 아직 목록에 있는 처방의 예상 수행시간 합. 예정 처방은 시각이 되기 전에 합계에 넣지 않는다.

현재 업무량 = 관찰 + 활력 + 대기 처방.

역할 카드는 이 식을 쓰지 않는다. 내부 비교값만 여유 15, 보통 40, 높음 60이고 화면에는 단계만 나온다.

단계: 급증이면 즉시 높음. 아니면 50분 초과 높음, 30분 이상 보통, 30분 미만 여유. 50분 정각은 보통이다.

1시간 뒤 값은 시연용 규칙이다. NEWS가 오른 폭만큼 점수를 더 올리고, 대기 처방의 60%, 60분 이내 예정 처방, KTAS별 기대 신규 처방(2 이하 8, 3은 4, 그 외 1)을 더한다. 학습 모델이 아니다.

지연: `현재 - 발생시각 > 목표시간`. 같으면 초과가 아니다. HTML은 우선 대상의 목표시간을 10분 줄여 초과 판정과 화면 기준을 같이 바꾼다.

인력: 환자가 있는 담당 간호사 수 × 50분. 추가 인력 1명당 50분을 더한다. 업무량/기준이 1 초과면 초과, 0.85 초과면 주의, 아니면 적정. 역할 간호사는 인력 수에 넣지 않는다.

지원 단계:

- 3단계: 인력 초과
- 2단계: 급증, 또는 지연 처방, 또는 높음이 15분 이상 지속
- 1단계: 높음 진입 또는 지원 필요 표시
- 이미 지원 중인 대상은 알림에서 뺀다.
- 추천: 본인 제외, 진행 중 지원의 지원자와 대상 제외, 단계가 높음이 아닌 사람 중 업무량 합이 가장 작은 사람. 이유 문구는 "업무량 최소".

09:00에 HTML 식으로 다시 계산한 값:

| 간호사 | 관찰 | 활력 | 대기 처방 | 합계 | 단계 |
| --- | ---: | ---: | ---: | ---: | --- |
| 김서연 | 41 | 12 | 83 | 136 | 높음 |
| 박도윤 | 15 | 4 | 15 | 34 | 보통 |
| 이하은 | 26 | 9 | 25 | 60 | 높음 |
| 최민준 | 6 | 2 | 3 | 11 | 여유 |
| 합계 | 88 | 27 | 126 | 241 |  |

김서연 초과 처방은 수혈 대기 40분(기준 30), 채혈 대기 35분(기준 30)으로 2건이다. 나머지 초기 처방은 기준 이내다.

시연 PDF 2페이지를 이미지로 확인한 09:00 표기는 김서연 40+12+83=135, 박도윤 15+4+15=34, 이하은 25+9+25=59, 최민준 8+2+3=13이다. 활력과 대기 처방은 HTML 계산과 같고, 관찰만 41 대 40, 26 대 25, 6 대 8이다. 네 명의 관찰 합과 총합은 둘 다 88분, 241분이다.

환자별 HTML 관찰은 다음과 같다. A-01은 KTAS 2와 NEWS 6으로 22분, A-02는 11분, A-03은 8분, 합 41분이다. B-01은 11분, B-02는 4분, 합 15분이다. C-01은 KTAS 2와 NEWS 4로 18분, C-02는 8분, 합 26분이다. D-01은 4분, D-02는 KTAS 5로 2분, 합 6분이다.

40, 15, 25, 8을 동시에 만드는 다른 KTAS, NEWS 표는 HTML에 없다. PDF 숫자는 같은 환자 구성의 표기값이고, 카드는 환자 데이터에 HTML 식을 적용한 값을 유지한다. 135, 59, 13으로 관찰 분만 덮어쓰지 않는다. 1시간 뒤도 PDF는 175, 44, 69, 13이고 HTML 식의 김서연 값은 164다. 맞추기 위한 계수는 넣지 않았다.

### 2.4. 버튼 동작

- `수행`: 처방을 목록에서 제거하고 수행자 `performed`에 예상 수행시간을 더한다. 지원 중이고 수행자가 지원자면 지원 기록의 건수와 분을 더한다. 완료 업무를 지원자의 남은 업무량에 다시 더하지는 않는다.
- `지원 필요`: 토글. 1단계 알림 조건이다.
- `우선 대상 지정`: 책임간호사만. HTML은 목표 수행시간 자체를 10분 줄인다.
- `지원 배정`: 추천 1명으로 즉시 지원을 시작한다. 수락 단계는 없다. 시작 시각은 배정 시각이다.
- `환자 재배정`: 2단계 이상이고 추천 대상이 환자 담당일 때. 급증 환자를 제외하고 2명 이상일 때 KTAS 숫자가 가장 큰 환자 1명을 옮긴다.
- `지원 종료`: 종료 시각을 기록한다.
- `급증 상황 해제`: 해당 간호사의 급증 플래그만 지운다. NEWS를 되돌리지는 않는다.
- `부서장 보고`, `추가 인력 투입`: 3단계 알림에만 있다.
- `처방 발생`: 환자 한 명과 처방 풀에서 시드 난수로 1건 추가
- `간호요구 급증`: HTML 순서는 D-01, A-02, C-02, B-02다. 종류는 호출마다 번갈아 붙고, 환자 상태 악화면 NEWS를 7 이상으로 올리고 관찰에 20분을 더한다. 시연 PDF 7페이지 알림은 D-02 `환자 상태 악화`이므로 구현의 첫 대상만 D-02로 바꿨다. NEWS 상승과 20분 가산은 HTML 버튼 동작을 유지한다.
- `초기화`: 난수 시드, id, 시각, 데이터, 지원, 로그를 처음 상태로 돌리고 보기를 책임간호사로 둔다. 자동 진행도 멈춘다.

| 09:30 | C-01 NEWS 4에서 6. A-02에 A-line 준비 추가(20분). A-03 예정 CAG가 대기 처방이 된다. |
| 09:40 | A-01 예정 조영 검사가 대기 처방이 된다. |
| 09:45 | D-03 신규 내원. 최민준, KTAS 3, NEWS 3, 활력 1시간, 채혈과 정맥 주사. |
| 10:00 | B-01 NEWS 4에서 5. C-02에 정맥 항생제. |
| 10:15 | A-01 NEWS 7에서 6. D-01에 채혈. |
| 10:30 | B-03 신규. 박도윤, KTAS 2, NEWS 5, 활력 30분, 채혈, 정맥 주사, Central line. |
| 09:50 | C-02 예정 조영 검사는 09:45에는 아직 예정이다. |

지원 배정, 수행, 종료는 버튼 시각을 따른다. PDF 흐름을 HTML 데이터로 재현하면 09:00에 배정하고, 지원자가 김서연 처방을 수행한 뒤, 09:15에 종료하면 시작 09:00, 종료 09:15, 15분이다. 수행 건수는 누른 처방 수다. PDF는 2건 수행을 설명하지만 자동으로 2건을 골라 주지는 않는다.

급증 버튼을 09:00에 누르면 이제 D-02가 대상이다. HTML 파일의 순서는 D-01부터다. PDF 7페이지는 09:45 화면이고, 최민준 31분은 관찰 8, 활력 2, 대기 처방 21로 읽힌다. 그 슬라이드는 관찰 20분 가산이나 D-02 NEWS 7이 아니라 다른 처방 구성이다. D-03 입실 같은 HTML 09:45 스크립트와도 다르다. 그 상태 전체를 새로 만들지 않았다.

### 3.1. 보기 차이

- 책임간호사: 전 카드 상세, 우선 대상 토글, 지원 알림, 배정, 재배정, 종료, 이벤트 기록
- 일반 간호사: 본인 카드만 상세. 동료는 단계, 환자 수, 지원 필요, 지원 중 여부 정도. 동료의 처방과 분 단위 업무량은 렌더링하지 않는다.
- HTML은 본인 카드에 우선 대상 태그를 보여 준다. 지원 알림 본문은 간호사 보기에서 숨긴다.

## 4. HTML, PDF, 간호부 답변의 차이

최신 업무 규칙은 2026-11-16 간호부 답변을 따른다. 화면 배치와 시연 숫자의 계산 절차는 HTML을 따른다.

| 항목 | HTML과 시연 PDF | 간호부 답변 | 이번 구현 |
| --- | --- | --- | --- |
| 인력 기준 | 담당 간호사 수 × 50분. 09:00은 4×50=200, 241분이라 초과, 3단계 | 담당 환자 수 × 50분. 50분은 임시값 | 환자 수 × 50. 09:00은 9×50=450, 241분은 적정. 구 3단계 알림은 만들지 않는다. 추가 인력 버튼은 기준에 50분을 더하는 시연 동작으로만 남긴다. |
| 우선 대상 10분 | 처방 목표시간을 10분 줄여 화면의 기준 초과와 알림에 같이 사용 | 처방 목표시간은 그대로, 지원 알림만 10분 앞당김 | 화면 기준 시간은 30 또는 60을 유지한다. 알림용 지연 판정만 10분을 앞당긴다. |
| NEWS ↑ | 이전 점수보다 크면 표시. A-01은 5에서 6이라 화살표가 나온다. | 양호 0~1, 주의 2~4, 위험 5~6, 고위험 7 이상. 단계가 오를 때만 화살표. 높은 점수는 색으로 구분 | 5에서 6은 같은 위험 단계라 화살표 없음. 6에서 7, 4에서 6은 화살표. |
| 지원 시작 | 배정 즉시 시작, 수락 없음 | 알림, 확인, 수락, 거절과 사유 | 배정 후 지원 간호사 화면에서 수락 또는 거절. 시작 시각은 수락 시각. |
| 추천 변경 | 추천 1명 버튼만 있음 | 다른 간호사 수동 선택 | 추천 배정 버튼과 다른 간호사 선택을 둔다. |
| 지원 불가 | 높음 단계와 이미 지원 중인 사람만 제외 | 휴식, 중증 환자 전담, 다른 업무 | 책임간호사가 사유를 표시하면 추천에서 뺀다. 초기 데이터에 없는 불가 인원을 만들어 두지 않는다. |
| 우선 대상 표시 | 책임간호사와 본인 카드 | 다른 간호사 화면에는 비공개 | 책임간호사 화면에서만 렌더링한다. |
| 수행 주체 | 책임간호사 화면에서 `지원자 수행`을 누름. 지원자 본인 화면에는 대상 환자 상세가 없다. | 배정 내용을 지원자에게 알리고 할 일을 넘긴다. | 동료 카드 상세는 열지 않는다. 수락한 지원자에게만 대상의 대기 처방 목록을 따로 보여 수행하게 한다. |
| 1시간 뒤 | 예측으로 표기 | 1차 범위 밖, 2차 연구 | 막대와 숫자는 남기되 `시연용`으로 표시한다. |
| 관찰, 활력 식 | HTML은 KTAS, NEWS, 주기, 회당 3분. PDF 2페이지 관찰만 1~2분 다름 | 모두 예상 소요시간. 문헌 검토 전이라 확정 식은 없음 | HTML 표를 `demoConfig`에 두고 카드 숫자는 그 합이다. PDF 135, 59, 13은 관찰만 다르므로 하드코딩하지 않는다. |
| 급증 환자 | HTML 버튼은 D-01부터. PDF 7페이지 알림은 D-02 | 악화 시 즉시 높음 | 첫 대상은 D-02. 라벨은 환자 상태 악화. NEWS를 7 이상으로 올리고 관찰 20분을 더하는 HTML 동작은 유지 |
| 09:00 추천 | HTML은 업무량 최소. 최민준 11분이 한지호 역할값 15분보다 작다 | 추천은 참고 | PDF 버튼 문구는 한지호다. 한지호를 우선하는 규칙은 HTML에 없어 최민준 추천을 유지 |
| 09:45 슬라이드 | PDF는 지원 종료 한지호 2건, 최민준 31분, 근무조 285/200 | 환자 수 x 50분 | HTML 스크립트의 09:45(D-03 입실 등)와 같은 상태가 아니다. 슬라이드 숫자를 초기 상태에 섞지 않는다 |
| 악화 시 높음 | 급증 플래그가 있으면 합계와 무관하게 높음 | 악화 시 즉시 높음, 사유 환자 악화. NEWS 5 이상 등이 악화 예시. NEWS 7 이상은 즉시 알림 | 급증 플래그는 즉시 높음. 시연 중 NEWS가 새로 5 이상 또는 7 이상이 되면 환자 악화로 높음과 알림을 올린다. 09:00에 이미 있던 A-01 NEWS 6은 새 이벤트가 아니라서 환자 악화 사유를 붙이지 않는다. |
| 4단계 | 없음 | 3단계가 30분 지속되면 부서 간 지원 | 구현하지 않는다. |
| 환자 번호 | A-01 같은 가상 코드 | 운영 시에는 환자명, 병상, 등록번호 | 시제품은 가상 코드만 유지한다. |
| 기술 | HTML 단일 파일 | 1차는 샘플 데이터 웹 시제품, Flow는 후속 | React, Zustand, Mock F1~F4 |

시연 PDF 문구는 HTML과 같다. 2페이지는 우선 대상의 수행 기준 10분 앞당김을 말하고, 3페이지는 배정 즉시 시작이라고 말한다. 이 두 문장은 간호부 답변과 충돌하므로 답변을 구현하고 이 문서에 차이를 남긴다.

## 5. 구현 가능한 기능과 모호한 기준

구현 가능:

- 현황판 레이아웃, 카드, 우측 패널, 시간 진행, 자동 진행, 처방 발생, 급증, 초기화
- 처방 수행, 대기 목록과 합계 갱신, 수행자 귀속
- 지원 추천, 수동 선택, 수락, 거절, 종료, 시작과 종료 시각, 수행 건수
- 구역 대기, 최장 대기, 기준 초과
- 책임간호사와 일반 간호사 렌더링 분기
- HTML 스크립트의 09:15, 09:30, 09:45, 10:00, 10:15, 10:30 이벤트
- F1~F4를 Mock 인터페이스 뒤에 두기

모호하거나 확정이 아님:

- KTAS, NEWS별 관찰 분과 활력 회당 3분, 급증 가산 20분
- 단계 경계 30분, 50분과 환자당 50분
- 높음 지속 15분. 답변은 15~30분을 설정값이라고 함
- 인력 주의 비율 0.85
- 1시간 뒤 시연 식의 잔존 60%와 KTAS별 기대 처방
- 추천의 세부 우선순위. HTML은 업무량 최소 1명
- 지원 불가 인원의 초기 명단. 데이터에 없음
- PDF 2페이지 관찰 40, 25, 8을 HTML 식 41, 26, 6과 같게 만드는 근거
- PDF가 한지호를 추천하는 정렬 규칙
- PDF 7페이지 09:45의 처방, NEWS, 31분을 재현하는 이벤트 목록
- 담당 환자 수 x 50분을 간호사 개인 지원 단계에 쓸지. 지금은 근무조 인력 적정성에만 쓰고, 개인 비교값은 단계와 따로 둔다
- 미분류 처방의 처리. HTML은 5분 후 낮음. 임의 등급은 주지 않음
- 4단계, 부서 간 지원, 과거 지원 기록 조회, AMIS 항목

## 6. React로 옮길 컴포넌트

HTML에 있는 구역만 컴포넌트로 나눈다.

- `DemoToolbar`: 제목 옆이 아니라 기존 툴바의 보기, 시간 진행, 자동 진행, 처방 발생, 급증, 초기화, 범례

- `SupportTaskList`: 수락한 지원자에게만 보이는 대상 처방. HTML에는 없고 답변의 할 일 전달을 위해 추가
- `SupportAlertPanel`, `AssignSupportDialog`, `RejectSupportDialog`
- `SupportHistoryPanel`, `StaffingPanel`, `ZoneTimelinessPanel`, `OpsSummaryPanel`, `OrderCatalogPanel`, `EventLog`
- `DemoNote`: 하단 주석

Store와 Mock이 합계, 단계, 지연, 알림을 계산한다. 카드는 그 결과를 표시한다.
